                  AI AGENTS IN DATA SCIENCE
===================================================================

1. OVERVIEW
-------------------------------------------------------------------
An AI Agent in data science is an autonomous software entity powered 
by Large Language Models (LLMs) that can perceive its environment, 
make decisions, and execute multi-step workflows to accomplish complex 
data tasks with minimal human intervention.

Unlike traditional scripts (which follow rigid, hardcoded rules) or standard 
chatbots (which only respond to single prompts), AI agents possess:
  - Autonomy: Ability to choose the best sequence of actions.
  - Tool Use: Ability to execute Python code, run SQL queries, and call APIs.
  - Memory: Short-term (context window) and long-term (vector databases) state.
  - Self-Correction: Ability to debug errors when code execution fails.


2. CORE ROLES & CAPABILITIES
-------------------------------------------------------------------
In a modern data science pipeline, AI agents operate across four primary 
stages:

[A] Automated Data Cleaning & Wrangling
    - Detecting missing values, outliers, and schema inconsistencies.
    - Generating and running pandas/PySpark transformations.
    - Imputing or dropping bad data based on context.

[B] Exploratory Data Analysis (EDA)
    - Automatically computing descriptive statistics.
    - Generating plots (e.g., Seaborn, Plotly) to identify distributions.
    - Summarizing statistical insights into natural language bullet points.

[C] Feature Engineering & Model Training
    - Formulating hypotheses for new feature candidates.
    - Selecting appropriate algorithms (e.g., LightGBM, XGBoost, PyTorch).
    - Running hyperparameter optimization (e.g., Optuna) iteratively.

[D] Reporting & Communication
    - Compiling insights into Markdown, PDF, or HTML dashboards.
    - Explaining feature importance and model trade-offs in plain business terms.


3. AGENT ARCHITECTURE & WORKFLOW
-------------------------------------------------------------------
A standard Data Science Agent architecture consists of four main components:

                   ┌──────────────────────────┐
                   │   LLM "Brain" (Logic)    │
                   └────────────┬─────────────┘
                                │
         ┌──────────────────────┼──────────────────────┐
         ▼                      ▼                      ▼
  ┌──────────────┐      ┌──────────────┐      ┌─────────────────┐
  │ Memory Bank  │      │  Tool Registry│     │ Code Execution  │
  │ (Context/RAG)│      │  (SQL, API)  │      │ Sandbox (Docker)│
  └──────────────┘      └──────────────┘      └─────────────────┘

Loop Mechanism (ReAct Framework - Reason & Act):
1. Plan: The agent analyzes the objective (e.g., "Find customer churn drivers").
2. Act: It writes and runs Python/SQL code in a secure sandbox.
3. Observe: It reads the output or error stack trace from the sandbox.
4. Refine: If an error occurs, it rewrites the code and executes again.


4. POPULAR AGENT FRAMEWORKS & ECOSYSTEM
-------------------------------------------------------------------
Frameworks commonly used to build data science agents:

- CrewAI / AutoGen: Multi-agent frameworks where specialized agents 
  (e.g., "Data Analyst Agent", "Machine Learning Engineer Agent") 
  collaborate on a shared goal.
- LangGraph: Enables deterministic, graph-based workflows with looping logic 
  for production-grade agent pipelines.
- OpenHands / OpenDevin: Open-source AI developer agents capable of writing, 
  testing, and debugging complex data science codebases.
- Advanced Data Analysis / Code Interpreter (OpenAI, Anthropic): Built-in 
  sandboxed execution environments inside conversational interfaces.


5. KEY ADVANTAGES
-------------------------------------------------------------------
- Speed: Reduces repetitive data exploration and cleaning from hours to minutes.
- Iteration: Can test dozens of model architectures and feature combinations 
  overnight.
- Accessibility: Allows non-technical stakeholders to ask natural language 
  questions and receive validated code and charts.


6. CURRENT LIMITATIONS & CHALLENGES
-------------------------------------------------------------------
- Hallucinations: Agents may misinterpret statistical results or draw invalid 
  causal conclusions.
- Security & Data Privacy: Running agents against production databases 
  requires strict sandbox boundaries and permissions.
- Cost & Latency: Multi-step reasoning loops consume significant token usage 
  and execution time.
- Human-in-the-Loop Requirement: Strategic domain expertise and business 
  context still require human oversight.
